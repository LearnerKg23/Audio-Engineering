## 1. What Is `demo.html`?

`demo.html` is the **Master Interactive Demonstration Interface** of our entire end-to-end Audio Engineering pipeline.

Instead of presenting dry command-line outputs or static plots to evaluators, `demo.html` is a **fully functional, single-file, zero-dependency Web Application** that brings all 4 stages of the pipeline to life in any modern web browser.

### 1.1 Key Capabilities of the Demo Interface
1. **Interactive Multi-Track Audio Switcher**:
   - Play the **Raw Overlapping Mixture** (Cocktail party speech).
   - Switch instantaneously to **Separated Stem 0 (Speaker 0 isolated)**.
   - Switch instantaneously to **Separated Stem 1 (Speaker 1 isolated)**.
   - All stems remain perfectly synchronized in playback time!
2. **Real-Time HTML5 Canvas Waveform Visualization**:
   - Displays live oscillating audio waveforms powered by the browser's native `AudioContext` and `AnalyserNode`.
3. **Synchronized Diarization Timeline**:
   - Visual color-coded timeline tracking each speaker's active speech turn.
   - Visualizes overlapping segments where both speakers speak concurrently.
4. **Speaker-Attributed Click-to-Seek Transcripts**:
   - Displays Hindi/Hinglish transcripts generated by AI4Bharat Vakyansh and Whisper.
   - Clicking on any word or turn automatically seeks the audio player to that exact millisecond.
5. **Contract 5 Structured Executive Report**:
   - Renders the final LLM-synthesized executive summary, primary topics, and key findings.

### 2.1 Why a Single-File Self-Contained HTML?
In corporate presentations, viva examinations, and portfolio reviews, loading external audio files often fails due to:
- Browser **CORS (Cross-Origin Resource Sharing)** restrictions when opening files via `file://`.
- Missing audio file paths when zipping or emailing a project folder.

To solve this, our script (`scripts/build_master_demo_html.py`):
1. Reads the output WAV files (`controlled_mix_01_pairAD_ov25_sir0.wav`, `stem_0.wav`, `stem_1.wav`).
2. Converts them into **Base64-encoded Data URIs** (`data:audio/wav;base64,...`).
3. Injects the complete JSON telemetry from all 4 milestones directly into JavaScript variables.
4. Outputs a single, portable `demo.html` that runs offline on any computer without needing an active Python server or internet connection!

## 4. How to Deploy Online for Everyone to Access

To share your work with professors, recruiters, or teammates so they can interact with the live demo on their phones or laptops without downloading any code:

### Option A: GitHub Pages (Recommended — 100% Free)
1. In your GitHub repository (`Audio-Engineering`), go to **Settings** $\to$ **Pages**.
2. Under **Build and deployment** $\to$ **Source**, select `Deploy from a branch`.
3. Choose branch: `main` and folder: `/ (root)`.
4. Click **Save**.
5. Within 1–2 minutes, your demo will be live at:
   ```text
   https://<your-username>.github.io/Audio-Engineering/demo.html
   ```

---

### Option B: Vercel / Netlify (Instant Drag & Drop)
1. Go to [vercel.com](https://vercel.com) or [netlify.com](https://netlify.com).
2. Connect your GitHub repository `Audio-Engineering`.
3. Set the output directory to root.
4. Click **Deploy**.
5. You receive an instant live URL with global CDN distribution.

## 5. Git Synchronization & Push Guide

If you ever encounter a git rejection error:
```bash
! [rejected]        main -> main (fetch first)
error: failed to push some refs to 'https://github.com/...'
hint: Updates were rejected because the remote contains work that you do not have locally.
```

This occurs because someone else (or another terminal session) pushed commits to the remote repository that your local branch has not incorporated yet.

### Step-by-Step Resolution:
1. **Pull the latest remote changes and rebase your local commits on top**:
   ```bash
   git pull --rebase origin main
   ```
2. **Stage your new learning documents**:
   ```bash
   git add LEARNING/
   ```
3. **Commit the changes with a descriptive message**:
   ```bash
   git commit -m "docs: add comprehensive deep dive learning suite for stages 1-4"
   ```
4. **Push cleanly to GitHub**:
   ```bash
   git push origin main
   ```
